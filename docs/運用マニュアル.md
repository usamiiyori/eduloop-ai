# EduLoop AI 運用マニュアル

このマニュアルはプログラミング知識のない方が読む前提で書かれています。各セクションはPhaseが進むごとに具体的な手順（画面名・ボタン名）で埋めていきます。

## 1. 初期セットアップ

### make コマンドの準備（Windows・初回のみ）

Windows には `make` コマンドが標準で入っていません。PowerShellを開き、次の1行を実行してください（`winget` はWindows 11に標準搭載）。

```
winget install GnuWin32.Make
```

インストール後、PowerShellを再起動してから `make setup` を実行してください（動作しない場合は環境変数PATHに `C:\Program Files (x86)\GnuWin32\bin` を追加する必要があります。その場合は改めてご連絡ください）。

（`make setup` 実行後の詳細手順は Phase 6 で画面付きに記載予定）

### Gemini APIキーの取得方法（Phase 4で必須）

生成AIによる記事下書き作成には、Googleの生成AI「Gemini」のAPIキーが必要です。無料枠があります。

1. ブラウザで **https://aistudio.google.com/** を開く
2. Googleアカウントでログインする
3. 画面上部（または左メニュー）の **「Get API key」** ボタンをクリックする
4. 「APIキーを作成」または **「Create API key」** ボタンをクリックする
   - プロジェクトの選択を求められた場合は、新規プロジェクトを作成するか既存のものを選ぶ（迷ったら新規作成でよい）
5. 作成されたキー（`AIza...` から始まる文字列）の右側にあるコピーアイコンをクリックしてコピーする
6. リポジトリ直下の `.env` ファイルを開き、`GOOGLE_GENAI_API_KEY=` の行の右側に貼り付けて保存する
   - `.env` がまだない場合は `.env.example` をコピーして `.env` を作成してから編集する
   - **このキーは他人に絶対に共有しない・GitHubにアップロードしない**（`.env` は `.gitignore` 済みで自動的に除外されます）

料金について（https://ai.google.dev/gemini-api/docs/pricing で2026-08-19確認、本システムの既定モデルgemini-2.5-flash）:
- **無料枠あり**: 入出力トークンは無料で使えます。ただし無料枠では「入力内容がGoogleのサービス改善に利用される」という条件が付きます。文科省の公開資料等、もともと公開情報のみを扱う本システムでは大きな問題にはなりにくいですが、認識だけしておいてください。
- **有料プラン**（内容が改善利用されない代わりに従量課金）: 入力 $0.30/100万トークン、出力 $2.50/100万トークン（テキストの場合の目安）。
- 料金体系は変更される可能性があるため、本格運用前に上記URLで最新情報を再確認してください。
- 本システムには `.env` の `LLM_DAILY_COST_LIMIT_USD` で日次コスト上限を設定する仕組みがありますが、実際にコストを計測して自動停止する処理はPhase 6で実装します（現時点では上限値を保持しているだけです）。

### 通知メールの設定方法（Phase 6で必須。2026-08-23、SlackからGmail通知に変更）

生成された記事の「レビューしてください」通知はメールで届きます（1日1回、夕方にまとめて。承認済み記事の公開完了通知・異常時の通知は都度届きます）。

**重要な設計方針**: 通知の送信元には、オーナー本人のプライベートなメールアドレスを使いません。**本人の身元とは紐づかない、通知専用のGoogleアカウント（お仕事用アカウント）**を1つ用意し、それを「収集先サイトへの名乗り」と「通知メールの送信元」の両方に使います。理由は、収集先の行政サイトに送るHTTPリクエストの名乗り（User-Agent）にこのメールアドレスが機械的に記録されるため、個人のメールアドレスをそのまま使うと本人の身元が外部から追跡できてしまうためです。**通知の宛先（実際にオーナーが読むメールアドレス）は外部には一切公開されません**。

**1. 通知専用アカウントの準備**

1. すでに専用のGoogleアカウント（お仕事用アカウント等）をお持ちの場合はそれを使う。なければ https://accounts.google.com/signup で本名と紐づかないユーザー名で新規作成する
2. そのアカウントで https://myaccount.google.com/security を開き、「**2段階認証プロセス**」をオンにする
3. 2段階認証をオンにしたら https://myaccount.google.com/apppasswords を開く
4. アプリ名を聞かれたら「EduLoop AI」等と入力し、「**作成**」をクリック
5. 表示された16桁の英字（この画面は再表示されないため必ずこの場でコピーする）を控える

**2. `.env` への設定**

```
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=（通知専用アカウントのGmailアドレス）
SMTP_APP_PASSWORD=（先ほどの16桁）
NOTIFY_TO_EMAIL=（実際に読みたいメールアドレス。プライベートのものでも専用アカウントと同じでもよい）
```

`SCRAPER_CONTACT_URL=mailto:（通知専用アカウントのGmailアドレス）` も同じアカウントを使って設定してください（収集先サイトへの名乗りと通知専用アカウントを統一するため）。

**3. GitHub Secretsへの登録**

上記5つの値（`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_APP_PASSWORD` / `NOTIFY_TO_EMAIL`）を、GitHubリポジトリの Settings → Secrets and variables → Actions にも同じ値で登録してください。

### Supabaseプロジェクトの作成方法（Phase 5で必須）

一次情報・生成記事・承認状態などのデータはSupabase（データベース）に保存します。

1. ブラウザで **https://supabase.com/** を開き、**「Start your project」** をクリック
2. GitHubアカウント等でログインする
3. **「New project」** をクリック
4. 組織（Organization）を選ぶか新規作成し、プロジェクト名（例: eduloop-ai）・データベースパスワード・リージョン（東京 = Northeast Asia (Tokyo) を推奨）を入力して **「Create new project」**
5. 数分待つとプロジェクトが作成される
6. 左メニューの **「Project Settings」** → **「Data API」** で **Project URL** をコピー → `.env` の `SUPABASE_URL=` に貼り付け
7. 同じ画面（または「API Keys」タブ）で **anon public** キーと **service_role** キーをコピーし、それぞれ `.env` の `SUPABASE_ANON_KEY=` / `SUPABASE_SERVICE_ROLE_KEY=` に貼り付け
   - **service_role キーは絶対に公開しない**（全データへの読み書き権限があります）
8. 左メニューの **「SQL Editor」** を開き、**「New query」** をクリック。このリポジトリの `sql/0001_initial_schema.sql` の中身を全部貼り付けて **「Run」** を押す（テーブルとセキュリティルールが作成されます）
9. 同様に `sql/0002_l2_review_queue.sql` の中身も貼り付けて **「Run」**（Web承認画面用の権限テーブル・関数が作成されます）

### 承認画面にログインできる人を増やす方法（2人目以降のレビュアー追加）

1. Supabase左メニュー「**Authentication**」→「**Users**」→「**Add user**」→「**Create new user**」で、追加したい人のメールアドレス・パスワードを入力（**「Auto Confirm User」を必ずON**にする）
2. 「SQL Editor」で次のSQLを実行（メールアドレス部分だけ書き換える）
   ```sql
   insert into reviewers (id, email)
   select id, email from auth.users where email = '追加したい人のメールアドレス';
   ```
3. これでそのアカウントも https://usamiiyori.github.io/eduloop-ai/ から承認操作ができるようになります

### 収集先サイトへの連絡先の設定（Phase 6・自動収集を有効化する前に必須）

自動収集(L1)は文科省等のサイトに自動でアクセスします。相手サイトの管理者が「このアクセスは何者か」と気になったときに連絡できるよう、HTTPリクエストの名乗り（User-Agent）に連絡先を含めるのがクローラーの一般的なマナーです。EduLoop AIの利用者（教員の方）向けの連絡先ではありません。

1. `.env` の `SCRAPER_CONTACT_URL=` に、メールアドレスなら `mailto:you@example.com` の形式、問い合わせページなら `https://example.com/contact` の形式で入力する
2. GitHubリポジトリの Settings → Secrets and variables → Actions で `SCRAPER_CONTACT_URL` という名前のSecretも同じ値で登録する
3. 設定できたら `.github/workflows/l1_collect.yml` の毎時自動実行(`schedule:`)を有効化してもらう旨をご連絡ください

未設定のままでも `workflow_dispatch`（手動実行）は可能ですが、毎時の自動実行は上記が設定されるまで意図的に無効化しています。

### GitHub Secretsの登録について

GitHub Actions（自動実行の基盤）は `.env` を直接読めないため、同じ値を GitHub リポジトリ側にも登録する必要があります（Settings → Secrets and variables → Actions → New repository secret）。Phase 6で以下を登録済みです。`.env` の値を変更した場合は、こちらも同じ値に更新してください。

`SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` / `GOOGLE_GENAI_API_KEY` / `GOOGLE_GENAI_MODEL` / `ARTICLE_SCORE_THRESHOLD` / `LLM_DAILY_COST_LIMIT_USD` / `HARNESS_MAX_RETRIES` / `X_PUBLISH_MODE` / `REVIEW_APP_URL`

`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_APP_PASSWORD` / `NOTIFY_TO_EMAIL` / `SCRAPER_CONTACT_URL` / `CONTACT_URL`（問い合わせ導線） / `NOTE_URL`（note有料マガジン）は未登録です。決まり次第、同じ画面から追加してください。

## 2. 日々の承認作業（L2）

**承認画面URL: https://usamiiyori.github.io/eduloop-ai/**（ブックマーク推奨。スマホ・タブレットのブラウザからも同じURLで開けます）

1. 記事の下書きがハーネス（自動検証）を通過すると、その日の夕方（1日1回まとめて）にレビュー依頼メールが届きます（対象記事のタイトル・スコア・確認用リンク付き）
2. 上記URLを開き、Supabaseで作成したメールアドレス・パスワードでログインする
3. レビュー待ちの記事が一覧に表示されます。各カードには次が表示されます
   - ①事実 ②現場への含意 ③まだ決まっていないこと・論点、本文プレビュー、出典
   - G1〜G6のハーネス検証結果（緑=OK、赤=NG）
   - 「要人間レビュー」バッジ（自己修復を3回試みても解決しなかった記事に表示）
4. 画面下部のボタンで操作する
   - **「承認」**: 内容に問題なければクリック→確認ダイアログで「OK」。次のL2実行タイミングでWeb公開・X下書き生成・note下書き出力の対象になります
   - **「却下」**: この記事は使わない場合にクリック→理由を入力して送信
   - **「修正指示を送る」**: 直せば使える場合にクリック→指示内容を入力して送信（次のL1実行で再生成されます）
5. 操作内容はすべて `audit_log`（監査ログ）に自動で記録されます

ログインできない・記事が表示されないなどの不具合があれば、エラーメッセージをそのまま伝えてください。

## 4. コストの確認方法

```
make cost
```

本日・今月のLLM推定コストを表示します。この金額はGemini有料プラン料金で計算した「上限見積り」であり、無料枠を使っている場合の実際の請求額は0円のことがあります。日次コスト上限（`.env`の`LLM_DAILY_COST_LIMIT_USD`、既定$3）に達すると、L1の自動収集はその日は自動的にスキップされ、メールで通知が届きます。上限を変更したい場合は `.env` と GitHub Secrets の両方の `LLM_DAILY_COST_LIMIT_USD` を書き換えてください。

**重要**: Google AI Studio側で実際に支払い上限（Billing Budget）を設定している場合は、`LLM_DAILY_COST_LIMIT_USD` を必ずその金額より低い米ドル換算値にしてください。EduLoop AI側の上限より先にGoogle側の上限に達すると、こちらのアプリは「原因不明のAPIエラー」としてしか検知できず、`make doctor`での診断も分かりにくくなります（2026-08-23、オーナーが¥500のBilling Budgetを設定していることを確認し、`LLM_DAILY_COST_LIMIT_USD`を$5→$3に変更した実例あり）。

## 5. 収集ソースの追加方法

`config/sources.yaml` に1エントリ追記するだけで、次回のL1実行から自動的に収集対象になります（コードの変更は不要です）。

```yaml
- id: 新しいソースのID（英数字とアンダースコアのみ、重複不可）
  name: 表示名
  axis: a_policy_jp   # a_policy_jp(行政・政策) / b_local_gov(地域・自治体) / c_global_academic(世界・学術・技術)
  fetch_type: rss      # rss / html_diff / pdf
  url: https://...
  license: unconfirmed # 利用規約を確認できたら該当する値に変更する
  attribution_required: true
  redistribution: quote_only   # full_allowed / summary_only / quote_only
  quote_max_ratio: 0.1         # redistribution が quote_only の場合のみ必須
```

`license` を `unconfirmed` のままにする場合、G2ゲート（出典・ライセンス検証）は最も厳しい `quote_only` 相当の扱いをします。追加後は必ずそのサイトの利用規約ページを確認し、正しい `license` 値に更新してください（CLAUDE.md 第4章）。

## 6. 停止方法（キルスイッチ）

```
make stop
```

実行すると、次回以降のL1(収集)・L2(承認連携)・L3(月次レポート)がすべて自動的にスキップされるようになります（GitHub Actionsのワークフロー自体は動きますが、開始直後に何もせず終了します）。

**再開する方法**: Supabaseの「SQL Editor」で次のSQLを実行してください。

```sql
update system_control set paused = false;
```

## 7. 法務上の注意（重要）

本システムは公的機関・学術機関の一次情報をスクレイピング・要約・引用して配信します。ソースごとのライセンス（`config/sources.yaml`）に応じた再配布ルールを自動チェックしていますが、これは設計上のリスク管理であり法的助言ではありません。**収益化（note有料化・企業案件化など）を本格的に進める前に、著作権・利用規約に詳しい専門家（弁護士等）に一度相談することを強く推奨します。**（詳細は `docs/ARCHITECTURE.md` 第5章）

## 8. X（旧Twitter）投稿について（費用に関する重要な注意）

X APIは2026年2月の制度変更により、新規開発者向けの無料枠が廃止されました。投稿1件につき$0.015（リンクを含む場合$0.20）の従量課金です。

**費用をかけたくない場合は `.env` の `X_PUBLISH_MODE=draft`（既定値）のままにしてください。** この設定では、システムはXスレッドの下書きテキストを作るだけで、実際の投稿はご自身でXアプリ・Webサイトから手動で行います。手動投稿はAPIを使わないため無料です。

自動投稿（`X_PUBLISH_MODE=api`）は費用が発生するため未実装のままにしています。将来的に自動化したくなった場合は改めてご相談ください。

## 9. GCPへの移行が必要になったら

現在の実行基盤はGitHub Actions（無料枠中心）です。以下のいずれかに該当した時点で、Google Cloud（Cloud Run + Cloud Scheduler等）への移行を検討してください（`docs/ARCHITECTURE.md` 第3章）。該当しない限り、移行の必要はありません。

- 1回の実行に15分を超える時間がかかるようになった（GitHub Actionsの実行時間制限に近づく）
- 常時起動しておきたい処理が必要になった（現在はすべて短時間のバッチ実行で完結する設計）
- 同時に大量のソースを並列で処理する必要が出てきた

該当しそうな場合は、その旨をお知らせください。移行方法を改めて設計します。
